How it works

Three steps. One approval.

The website owns the challenge and the session. DsxID only signs what you explicitly approve.

01

Create your identity

Choose a passphrase. DsxID generates and seals an Ed25519 key on this computer.

02

Approve the request

A site asks for a signature. Check the origin and the profile fields, then approve.

03

The site verifies it

Your backend checks the signature, challenge, origin and expiry, then creates its own session.

For developers

A small SDK. A clear contract.

Mount a button, request the profile fields your checkout needs, and verify the signed assertion on your backend.

checkout.js 
DsxID.mount("#checkout", {
  startUrl: "/api/dsxid/start",
  verifyUrl: "/api/dsxid/verify",
  profile: ["fullName", "email",
            "address1", "city",
            "postalCode", "country"],
  onSuccess: function (result) {
    for (const [key, value] of
      Object.entries(result.profile || {})) {
      const input = document.querySelector(
        `[name="${key}"]`
      );
      if (input) input.value = value;
    }
  }
});

Security by default

Nothing leaves unless you say so.

No telemetry, no cloud, no password database. The private key and profile stay under your control.

Local by design

Identity, profile and approvals are stored in %APPDATA%\DsxID. The app makes no external network calls.

Origin-bound signatures

Every assertion covers the website origin, challenge and expiry. A man-in-the-middle cannot forge or alter it.

You see the fields

The approval dialog lists every profile value that will be shared. Missing values are shown as not shared.
